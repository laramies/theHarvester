# Research for judgment-based coding standards

Date: 2026-09-26. Scope: Python 3.14 and aiohttp 3.14.3, as pinned in [`pyproject.toml`](../pyproject.toml). This note informs `CODING_STANDARDS.md`; it does not replace the project contracts in [`docs/architecture.md`](architecture.md), [`CONTRIBUTING.md`](../CONTRIBUTING.md), and the [discovery module guide](wiki/How-to-add-a-new-module.md).

## Recommendations

| Judgment standard for review | Mechanical check to keep separate | Basis |
| --- | --- | --- |
| Trace the **whole provider conversation** before changing network, pagination, retry, proxy, cookie, or cancellation behavior. Name the owner of each session, response, connector, and spawned task; distinguish owned resources from borrowed ones. Confirm the state needed by a later request survives and no state crosses source executions or targets. | Ruff, typing, and a local lifecycle test can catch specific mistakes, but cannot infer the intended ownership boundary. | The [module guide](wiki/How-to-add-a-new-module.md#own-the-provider-conversation) defines this boundary. aiohttp says a session owns a connector by default, supports a private cookie jar, and closes via its context manager; `connector_owner=False` changes connector ownership ([client reference](https://docs.aiohttp.org/en/v3.14.3/client_reference.html#client-session)). |
| Preserve cancellation as cancellation after cleanup. Review every `await`, exception handler, and task it can interrupt. Verify cleanup on success, transport failure, and interruption, and preserve retained evidence according to the central runner's contract. | A focused offline cancellation test can assert resource closure and propagated `CancelledError`; passing it does not prove every related branch was audited. | Python recommends `try/finally` for cleanup and generally re-raising `CancelledError`; swallowing it can break `TaskGroup` and timeouts ([Python 3.14 asyncio tasks](https://docs.python.org/3.14/library/asyncio-task.html#task-cancellation)). The [architecture guide](architecture.md#execution-and-lifecycle) separates source and run outcomes and retained evidence. |
| For related pages, retries, or polling, decide whether provider state must persist. Reuse the borrowed session when cookies, headers, connection pool, or selected proxy are part of the conversation. Use a deliberately empty cookie jar for independent probes. Check proxy selection at both session creation and each request, including helpers called with a borrowed session; session reuse alone does not prove proxy identity stays fixed. | An offline second-page test can require a cookie or other first-page state, assert the selected proxy, and assert session closure. A linter cannot establish the provider's state contract. | aiohttp documents session cookie sharing and `DummyCookieJar` ([advanced usage](https://docs.aiohttp.org/en/v3.14.3/client_advanced.html#custom-cookies), [client reference](https://docs.aiohttp.org/en/v3.14.3/client_reference.html#client-session)); its proxy settings can be passed at session or request level ([proxy support](https://docs.aiohttp.org/en/v3.14.3/client_advanced.html#proxy-support)). Project-specific behavior is in [`AsyncFetcher.open_session()` and `fetch()`](../theHarvester/lib/core.py) and the [module guide](wiki/How-to-add-a-new-module.md#own-the-provider-conversation). |
| Make review claims proportional to evidence: identify the changed contract and concrete before/after behavior, name the exact test or check run, and distinguish static source inspection, offline tests, CI, publication, and live provider behavior. Treat a test as useful only if it would fail on the relevant regression. | CI can report command results, coverage gates, and diff metadata; a reviewer still decides whether assertions cover the behavior and whether operator documentation changed. | [`CONTRIBUTING.md`](../CONTRIBUTING.md#open-a-pull-request) asks for before/after behavior, exact checks, and risks. Google's first-party [review guidance](https://google.github.io/eng-practices/review/reviewer/looking-for.html) calls for checking edge cases, concurrency, test validity, and documentation. GitHub [separates diffs, discussion, and checks](https://docs.github.com/en/pull-requests/get-started/about-pull-requests). |

## Project fit and caveats

- The source catalog and runner own identifiers, selection, final status, and normalized evidence; adapter review should not invent a parallel outcome mechanism ([architecture](architecture.md#execution-and-lifecycle), [module guide](wiki/How-to-add-a-new-module.md#2-implement-the-adapter)).
- The project uses offline provider contract tests and blocks routine external socket traffic. Those tests establish local behavior; live provider drift remains a separate, authorized integration question ([CONTRIBUTING.md](../CONTRIBUTING.md#test-safely)).
- `AsyncFetcher.fetch()` currently resolves its `proxy` argument even when given a borrowed session. A standard should require caller-path inspection before asserting fixed proxy identity, rather than assume it from aiohttp session reuse alone ([core.py](../theHarvester/lib/core.py)).
- These are review judgments, not new automatic gates or claims that all existing adapters conform. The linked aiohttp pages are versioned 3.14.3 documentation; exact project behavior must still be checked in the pinned code path.

## Retrospective findings

1. Review guidance was embedded in the always-loaded agent instructions. Move it to `CODING_STANDARDS.md` and retain a review-triggered pointer. Preserve the four existing review subjects: compatibility, sensitive data, reconnaissance boundaries, and provider resource lifetime. The architecture and module guide remain the owners of detailed behavior contracts.
2. Mechanical checks already have a CI path: [Python CI](../.github/workflows/theHarvester.yml) runs lint, formatting, pytest, and typing. The [test harness](../tests/conftest.py) enforces offline Python networking, and [provider coverage](../tests/test_provider_contract_coverage.py) checks catalog registration. Add judgment about coverage quality without duplicating those checks in prose.
3. Test-code linting and typing remain a separate improvement candidate: [Ruff excludes tests and ty includes only the application package](../pyproject.toml). Browser verification has a [separate workflow](../.github/workflows/harvestview-e2e.yml). This documentation change does not expand those gates or claim whole-repository coverage.
